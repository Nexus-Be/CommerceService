# Implementation Plan: Fulfillment Integration Remediation and Architectural Alignment

**Branch**: `012-commerce-fulfillment-remediation` | **Date**: 2026-11-04 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/012-commerce-fulfillment-remediation/spec.md`

---

## Summary

This plan details the technical steps to remediate critical integration misalignments with `FulfillmentService` (Port 8006), enforce strict Fail-Closed error handling (RFC 9110 HTTP 503), harmonize reservation reference identifiers between checkout and sub-order rejection, eliminate the false "Zero-HTTP" assumption in `PaymentTimeoutWorker`, expand webhook delivery status mappings to 9 lifecycle states, and ratify the project constitution to Version 1.4.0.

---

## Technical Context

**Language/Version**: C# 12 / .NET 8.0 LTS  
**Primary Dependencies**: ASP.NET Core 8.0, Entity Framework Core 8.0, Npgsql.EntityFrameworkCore.PostgreSQL, System.Net.Http.Json  
**Storage**: PostgreSQL 16 (Port `5435`, database `commerce_db`) via `ICommerceDbContext` (No Repository Pattern)  
**Testing**: xUnit, FluentAssertions, Moq, Testcontainers (optional)  
**Target Platform**: Linux/Windows Container, ASP.NET Core Kestrel (Port `8003`)  
**Project Type**: RESTful Web Service & Background Worker  
**Performance Goals**: Concurrent batch processing under 200ms p95; zero thread blocking during inter-service HTTP calls  
**Constraints**: Inward-Only boundaries; zero mock fallbacks; 100% English sentence-case error messages; zero message brokers  
**Scale/Scope**: 4 core files modified (`DependencyInjection.cs`, `FulfillmentClient.cs`, `OrderService.cs`, `PaymentTimeoutWorker.cs`), unit test suite additions, and constitution update

## Complexity Tracking

> No constitution violations detected. No complexity justifications required.

| Aspect | Selected Pattern | Reason & Tradeoff |
| :--- | :--- | :--- |
| **Delivery Status Mapping** | State mapping to `Cancelled` + `OrderCancellation` | Avoids modifying PostgreSQL enum schema for `SubOrderStatus` while preserving full auditability. |
| **Payment Timeout Stock Release** | Asynchronous HTTP with `InventoryReleased = false` fallback | Prevents temporary network partitions from blocking customer order state cancellation. |
| **SubOrder Rejection Release** | Master `orderId` reference with `itemsToRelease` JSON payload | Matches Fulfillment's reservation storage model without requiring sub-order-level reservation fragmentation. |
